Recommendations in the table are technical suggestions, not decisions.** Source columns are kept apart: "Frozen text" quotes the specification v2.7 or the proposed MD-08 text (`MASTER_PROPOSED_DECISION_RECORD.md`, which is a proposal, not an adopted record); "Code and tests" states what `s10_runner.py`, `s10_resume.py`, `s10_integrity.py` do today and which mock-provider test shows it (research_design/step10; 182 tests passed on 2026-10-14); "Assistant recommendation" is a technical suggestion only.

Background facts shared by all rows:
- Spec 13.8: halting is the only action of the monitor; "A run interrupted by transport failure resumes only under the identical FZ version (plus any pure implementation fix under H1-H4), continuing at the next `call_index` of the same frozen order (no re-draw)". "A transport-only halt (SF1) may resume only under the identical FZ version"; "no completed call is replaced or discarded; no call is silently substituted"; "failed calls are not selectively re-run"; "nothing is pooled with a later run".
- Spec 13.4 table: **SF1 = "Transport failure: HTTP/API error or timeout"** (so the specification's SF1 includes HTTP/API errors).
- Spec 13.6 "Pure implementation fix (H1-H4)": the only change allowed to executable code at any time; H1 touches executable code only; H2 byte-identical behaviour on the frozen synthetic regression suite; H3 agreement with the frozen reference grammar checker for the triggering record; H4 logged (code hash before and after, regression result, reason class `crash`/`hang`/`logging`/`I/O`; the harness code hash is recorded in the run manifest). Versioning rule: any change to timeout, delay, retry count, a prompt character, etc. is a new FZ version and needs a re-pilot.
- Resume is implemented only as a fail-closed module (`s10_resume.py`). It is not adopted by any decision record. Without a decision, an interrupted run is simply lost as a run (it cannot be reported or continued).
