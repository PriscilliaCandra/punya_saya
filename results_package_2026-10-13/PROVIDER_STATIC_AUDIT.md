# Static audit of the Gemini adapter and the runner (no network request was made)

Sources read: `research_design/step10/s10_runner.py` (`GeminiProvider.generate`, `run`, `check_gates`), `s10_scoring.py`, `s10_integrity.py`, `PARAMETER_FREEZE_MANIFEST_FZ_v1.json` row 17, decision record 12.11 (OD-9, OD-10), 12.30. Result classes: OK = matches the frozen text by reading the code; GAP = a defect or missing piece found by reading; LIVE = can only be settled by one authorized live connection test.

| # | Aspect | Finding | Class |
|---|---|---|---|
| 1 | Model and settings | The register values (`gemini-3.5-flash-lite`, thinking minimal, 8192 output tokens, retries 0, timeout 180 s, delay 1 s, concurrency 1) are compared with hard-coded expected values in `check_gates`; any difference closes the gate. Temperature is not sent; no system prompt is sent. | OK |
| 2 | Request field names | `generationConfig.maxOutputTokens` and `thinkingConfig.thinkingLevel` are written from memory of the public REST shape and have never been checked against the live API or its current documentation for this model. A wrong name could be ignored silently (thinking level) or rejected (HTTP 400 = SF1 for every call). | LIVE |
| 3 | Retries | `urllib` does not retry; the loop calls the provider once per call key; `test_pilot_records_failures_without_retry` shows 18 calls for 18 keys. | OK |
| 4 | Timeout | `urlopen(timeout=180)` is a per-socket-operation timeout, not a total deadline: a slow trickling response could exceed 180 s. The frozen text says "timeout 180 s" without defining which. | GAP (documented; owner may accept) |
| 5 | Concurrency and delay | Sequential loop; `sleeper(1)` between calls, not after the last call. | OK |
| 6 | Failure never replaced by another response | A provider exception becomes `error=<class name>`, empty text, recorded and classified SF1; HTTP errors keep only the status code; the call is not repeated and no other model or text is substituted. | OK |
| 7 | Failure not recorded as success | `classify` returns SF for error-without-text, empty text, `MAX_TOKENS`, listed block reasons and HTTP 200 without candidate text. The summary status `RUN_COMPLETE` means only "every planned call has a record", not "every call succeeded"; reports use the classes. | OK, naming caveat |
| 8 | Unknown finish reasons | Only `MAX_TOKENS` is SF3 and `SAFETY, BLOCKLIST, PROHIBITED_CONTENT, SPII, IMAGE_SAFETY, RECITATION, OTHER, LANGUAGE` are SF4. Any other non-`STOP` reason (for example a malformed-output reason) with text present is scored as an ordinary response. | GAP / LIVE (which reasons exist is a provider fact) |
| 9 | Multiple parts | The text is the concatenation of all `parts[].text` of the first candidate. If a part is flagged as model "thought" it would be included. With thinking minimal and no `includeThoughts` this is not expected. | LIVE |
| 10 | Returned model ID | `modelVersion` is stored as `model_returned`; nothing halts a run if it differs from the requested ID. `s10_integrity` lists the set; a difference is visible but not a stop rule. | GAP (specification asks for the ID to be recorded, FZ-v1 row 17; no stop rule exists) |
| 11 | Usage metadata | `usageMetadata` is stored verbatim. `s10_integrity` computes the observed cost from `promptTokenCount` and `candidatesTokenCount` only. If the live API reports thinking tokens separately (`thoughtsTokenCount`, billed as output), the observed cost is under-counted. The 70 recorded Stage 1/2 calls have no such field. | GAP (small code change; not applied) |
| 12 | Latency | `GeminiProvider` returns no `latency_ms`, so records store `null`. Latency is a reported quantity of the pilot analysis (13.7) and used nowhere in a decision. | GAP (small code change; not applied) |
| 13 | Missing key | If `GEMINI_API_KEY` is absent, every call is recorded as SF1 "no API key". Started by mistake, this would consume a pilot round (cap 2) with 18 recorded failures. The runner does not check the key before the first call. | GAP (important; preflight check, no network, not applied) |
| 14 | Secrets | The key is read from the environment, sent only in the `x-goog-api-key` header, never stored; exception text is reduced to the class name; the HTTP error body is discarded. The key does not appear in `calls.jsonl`, `raw/`, `ledger.jsonl` or the summary. | OK |
| 15 | Cost source | The pre-run ceiling uses the owner-stated tokens per call and the register output cap (hard cap, OD-10); the post-run figure uses recorded usage and the prices stored in the FZ-v1 manifest (read from provider pages on 2026-10-12, not re-verified since). | OK, prices to re-verify before the first paid call (PJR J-9) |
| 16 | Stop rules | Main run: `main_run_halt` after every call (13.8). Pilot: no halt inside a round (13.6 decides on counts). Resume of a transport-halted main run under the same FZ version (13.8) is NOT implemented: an existing output folder is refused. | GAP (NOT_STARTED component) |
| 17 | Response content exposure | The runner prints no response text; but `raw/*.json` and `calls.jsonl` contain it. Humans must not open them for the pilot (13.6.1 activity B, 22 item 17). | OK, human rule |
| 18 | Whitelisted changes after a round-1 FAIL-S | Timeout, delay, retries, max tokens are hard-coded as the only accepted values; a whitelisted change (13.6) needs a new FZ version and a code/expected-value update before round 2. | Documented limit |

## What only one authorized live connection test can settle
Items 2, 8, 9 and the existence of `thoughtsTokenCount` (11): one call is enough to see the accepted field names, the returned `modelVersion`, the finish-reason vocabulary and the usage fields. It needs the owner's written authorization and a cost note; it was not run. Such a call is not a pilot call and its response would be protocol-relevant content, so how it is handled (discarded, unread) should be decided by the owner first.

## Small code changes recommended (NOT applied; each needs a test)
(a) key preflight before the first call (13); (b) add `thoughtsTokenCount` to the observed cost (11); (c) measure `latency_ms` in the run loop (12); (d) optional stop on a returned-model mismatch, only if the owner wants it as a rule (10).

## Update after the pre-pilot fixes (see `PRE_PILOT_FIX_REPORT.md`, decision record 12.34)
Item 13 (missing key): FIXED, local preflight before any folder or ledger entry exists. Item 12 (latency): FIXED, wall-clock latency is recorded when the provider gives none. Item 11 (thinking tokens): FIXED in the accounting tool without double counting; whether the live API reports the field remains LIVE. Item 4 (timeout): behaviour unchanged by design; the run summary now states "per socket operation, no total deadline" and the integrity tool flags calls whose recorded latency exceeds 180 s; whether a total deadline is wanted is an owner decision. Item 16 (resume): not implemented, specification problem written up. Items 2, 8, 9, 10 are unchanged.
